# Awaaz — Phase 1b contract (extends docs/CONTRACT.md)

User requirements driving this phase (2026-11-11):
1. **Reporting is the flagship**: a short spoken *conversation with the AI*. The user can give as much detail as they
   want; the AI asks at most 3 short follow-up questions (spoken aloud in Urdu/English, each with big icon quick-reply
   chips so an illiterate user can tap instead of talking). Default attribute list + AI-generated category-specific ones.
   User can mark Emergency / Urgent / Can wait. Emergency → submit immediately, no more questions. Goal: meaningful
   information in the least time.
2. **Voice edge cases**: silence, too short, noise, unintelligible, off-topic — never create a report from silence;
   speak a friendly prompt and let them retry.
3. **Illiterate-first onboarding**: language pick → dummy phone number → mock SMS code shown on screen (tap to fill) →
   profile by ONE spoken question ("tell us your name and your area") → AI extracts → read-back for trust → confirm.
4. **Voice guidance everywhere**: a speaker button on each key screen saying what is being asked (pre-recorded clips).
5. **Map = Leaflet + OpenStreetMap** (no Google Maps).
6. Admin panel (see everything) is the LAST step — not in this phase.

## Edge Functions (new / changed)
### `report-chat` POST — one intake turn. Request/response = `ReportChatRequest` / `ReportChatResponse` (src/lib/attributes.ts).
- requireUser. If `audio_path` → transcribe (must start with `<uid>/`). **Silence / no-speech**: empty transcript, < 2 words of
  real content, or known STT hallucinations ("thank you for watching", "subscribe", lone "شکریہ", music/noise markers) →
  `no_speech: true`, reply = noSpeech text, same attributes, turn not incremented, no AI call.
- Otherwise ONE OpenAI call (`ai.ts` new export `intakeTurn`) with strict JSON output:
  `{ reply_en, reply_ur, quick_replies[≤4], attributes (full updated map), draft, ready, emergency, ask_photo }`.
  Rules for the model: Pakistani context; ask only what matters most for responders for THIS category; one short question per
  turn (≤ 15 words), simple words; never re-ask known info; prefer yes/no or tap-able options (quick replies with icons from
  ATTRIBUTE_ICON_NAMES); fill DEFAULT_ATTRIBUTES + category hints from anything the user already said; `emergency` = immediate
  danger to life (fire with people, unconscious person, live wire on road, drowning, violence in progress) OR user says
  emergency; `ready` when enough to act or turn >= MAX_INTAKE_QUESTIONS; when ready, reply = short bilingual confirmation of
  what will be sent ("Open manhole near the school on Street 5, children at risk. Sending now?").
  The first turn always offers the 3 user-urgency chips (emergency / urgent / can_wait) unless urgency is already clear.
- Reply audio: TTS of the reply in `ui_language` via ai.speak + the tts-cache bucket (share the cache helper with tts/index.ts) →
  `reply_audio_url`. Do TTS in parallel with nothing blocking; if TTS fails, omit the URL (client shows text + plays nothing).
- Latency target: < 6 s per turn. Use `reasoning.effort` "none" or "low" for intakeTurn (pick the faster that is reliable;
  the phase-aware output parser handles the extra commentary item).
### `process-report` (changed) — accepts extra optional fields:
  `conversation?: ChatTurn[]`, `attributes?: AttributeMap`, `user_urgency?: UserUrgency`, `intake_session_id?: string`,
  `audio_paths?: string[]` (all voice turns, stored as report_media). When `conversation` is present, DO NOT re-transcribe:
  build the extraction input from the user turns' text (+ the AI questions for context) and pass attributes + user_urgency to
  extractReport (urgency: user 'emergency' ⇒ at least high; AI may raise to critical; never below the user's choice by more
  than one level and say why in confidence_notes). Store attributes/conversation/user_urgency. Silence rules also apply to the
  single `audio_path` path: no speech + no text + no photo ⇒ HTTP 200 `rejected {reason:'no_speech', message_en, message_ur}`.
### `voice-profile` POST `{ audio_path?: string; text?: string; ui_language: 'ur'|'en' }`
  → `{ transcript: string; no_speech: boolean; profile: { display_name: string|null; home_area: string|null;
       language: 'ur'|'en'|null }; confirm: { en: string; ur: string }; confirm_audio_url?: string }`
  ai.ts new export `extractProfile(text)` (strict JSON; names in their original script + a Latin transliteration is NOT needed;
  home_area normalised like "G-9/4, Islamabad"). Confirmation text e.g. "Your name is Ayesha and you live in G-9. Is that right?"
  + TTS clip in ui_language.

## SOS — women's safety (user requirement 2026-11-11)
Normal reporting stays as is. SOS is a separate, very specific emergency mode that opens the mic, listens discreetly,
and — when the AI hears a threat ("I'll kill you", "maar dunga", "jaan se maar doon ga", "chhor do mujhe", "bachao",
"help me", kidnapping / coercion / assault language, pleading, screaming markers) — sends an URGENT alert to nearby police
with live location, and logs it in the user's app.
**SOS is silent**: never play voice prompts or sounds in SOS mode (it could alert an attacker) — vibration only.
**SOS is private**: never on the public map.

### Triggers (frontend)
- Red SOS button: on MapPage (top, start side) and MePage. Press-and-hold 1.5 s with a filling ring (prevents accidents) →
  navigate('/sos?trigger=button').
- Hardware volume buttons (best effort): a global listener (mounted app-wide) for keydown `AudioVolumeUp`/`AudioVolumeDown`
  (also legacy `VolumeUp`/`VolumeDown`, keyCodes 174/175/182/183): 3 presses within 2.5 s → '/sos?trigger=volume'.
  LIMITATION (say it in the UI help + README): browsers deliver volume keys only on some Android devices and only while the
  app is open in the foreground; screen-off/background triggering needs a native wrapper (TWA + Android service) — future work.
- Shake: opt-in toggle in MePage ("shake phone 3 times for SOS"), DeviceMotion, 3 strong shakes in 2 s (iOS needs
  DeviceMotionEvent.requestPermission on a tap) → '/sos?trigger=shake'.
- App-icon shortcut "SOS" in the web manifest → '/sos?trigger=shortcut'.
- Settings are per-device (localStorage, try/catch).

### SOS screen (`/sos`, RequireAuth — anonymous OK)
Full screen, dark. Starts immediately: `sos` start → mic recording in self-contained `SOS_CHUNK_SECONDS` (8 s) chunks
(restart MediaRecorder per chunk so each file decodes on its own) → upload `report-audio/<uid>/sos/<session_id>/<seq>.webm`
→ `sos` chunk. High-accuracy location watch → `sos` location every ≥ 15 s or ≥ 25 m moved. UI: pulsing "Listening" ring,
timer, status line (Listening… / Police alerted ✓ with org name), huge "Send alert now" (manual escalation, no AI needed),
"I'm safe" (end, outcome safe; confirm with hold), "Disguise" toggle that blacks out the screen (tap 3× to undo).
Wake Lock API while active. If mic is denied → still allow "Send alert now" with location.

### `sos` Edge Function — POST, requireUser, body = `SosRequest`, response = `SosResponse` (src/lib/sos.ts)
- start: insert sos_sessions (id = client session_id, idempotent), status 'monitoring'.
- chunk: path must start with `<uid>/sos/<session_id>/`; transcribe (silence ⇒ no_speech, skip AI); append to
  sos_sessions.transcript; `threatCheck` (new module `_shared/threat.ts`, OpenAI MODELS.reason, strict JSON
  {threat_level: none|possible|high, phrases[], reason_en, reason_ur}) over the last ~3 chunks; plus a deterministic keyword
  list (Urdu script, Roman Urdu, English) that forces 'high'. On 'high' (first time) → escalate.
- alert: manual escalate (reason "User pressed Send alert").
- escalate = create PRIVATE cluster + report (category 'safety', urgency 'critical', is_private true, user_urgency 'emergency',
  status 'unconfirmed', title "SOS — possible threat"/"ایس او ایس — ممکنہ خطرہ", summary from reason + key phrases, attributes
  {threat_phrases, trigger, live_location}), set clusters.sos_session_id, then route ONLY to police orgs (find_responders
  with p_category 'safety', ignore verification), notifications type 'sos_alert' (police owners) + FCM push (urgent wording,
  link /dashboard), session status 'alerted', alerted_at, cluster_id; user notification type 'sos_logged'.
- location: update sos_sessions.last_location(_at) and, if alerted, the cluster centroid + report location (police map follows).
- end: status 'safe' | 'cancelled', ended_at; if alerted, notify police "User marked themselves safe" (assignment stays for
  police to resolve).
- evidence: police owner of an assigned org (or admin) → signed URLs (1 h) for the session's chunks + transcripts.
Latency target per chunk < 5 s. Never throws to the client for AI failures — keyword check still runs.
